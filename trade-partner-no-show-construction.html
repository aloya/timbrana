Project scenario · No-show

A trade partner was scheduled for today and never arrived. What should the project record show?

A no-show is different from ordinary absence. It means the project had a specific commitment that was not met, and that missed commitment may affect other work.

Construction project scenarioUpdated September 28, 2026

Mark the commitment as a no-show

Do not simply delete the scheduled event or move it to tomorrow. Preserve the fact that the original commitment was missed.

Decide whether it needs attention

If nothing else depends on the work, the no-show may remain a scheduling exception. If another trade, inspection or milestone is affected, surface the item so the consequence is visible.

Do not fabricate a communication

If nobody called the trade partner yet, the system should not imply that contact occurred. The no-show itself is enough to create the need for follow-up.

Reschedule the same commitment

When a new date is agreed, reschedule the existing item. The project history should show scheduled, no-show and rescheduled rather than three unrelated entries.

Use patterns carefully

One missed day is a project fact. Repeated no-shows may become useful history for project management, but the operational goal is still to manage the current commitment rather than turn the system into a performance scorecard.

The goal is one understandable project thread.

Keep the original condition or communication, the current responsibility and the next action connected instead of recreating the same item in multiple places.

How this fits Timbrana

Timbrana is designed so everyday project activity can move into the workflow that owns the next step while preserving where the item came from. That can mean an issue, scheduled event, owner question, RFI, change order or personal follow-up depending on what the project actually needs.
